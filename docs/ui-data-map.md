# خريطة الواجهة والبيانات — MowxBack

هذه الخريطة مبنية على حقول النماذج وعناصر الصفحة والإجراءات الفعلية في `js/app.js`، وليست نموذجاً محاسبياً عاماً. جميع قيم المبالغ في خريطة SQLite تمثل وحدات صحيحة `amount_milli` (ألف جزء من وحدة العملة)، والكميات تمثل `quantity_micros` (مليون جزء من وحدة الكمية).

## 1. صفحات التطبيق

| الصفحة/المكون | ما يظهر حالياً | البيانات المقروءة | مصدر الحفظ في SQLite | ملاحظات الربط |
|---|---|---|---|---|
| الرئيسية `home` | صافي اليوم، أرباح، مصروفات شاملة السحبيات، السحبيات كتفصيل، آخر 8 عمليات، أزرار سريعة | عمليات تاريخ اليوم | `v_daily_totals`, `v_all_transactions` | لا يوجد رصيد صندوق أو نقدية متبقية |
| دفتر اليوم `ledger` | تاريخ محدد، صافي وملخص اليوم، أقسام كل نوع | حركات التاريخ المحدد | `v_daily_totals`, `v_all_transactions` | التاريخ قابل للاختيار وقد يكون سابقاً |
| أرباح الأصناف `profits` | نطاق من/إلى، الإجمالي والكمية، الحركات المجمعة، إجمالي حسب الصنف | رأس حركة الربح ومجموع خطوطها | `profit_transactions`, `profit_lines`, `v_profit_transaction_totals`, `v_profit_by_item` | حركة واحدة في القائمة لكل `profit_transactions.id` |
| تفاصيل حركة الربح | التاريخ، صفوف المنتجات، الكمية، إجمالي الربح، ملاحظات، تعديل/حذف | خطوط الحركة الفعالة وكل الخطوط التاريخية عند الحاجة | `profit_lines` + `audit_log` | حذف السطر Soft Delete ولا يحذف بقية السطور |
| المصروفات `expenses` | فترة، إجمالي، قائمة، تفصيل حسب التصنيف | المصروفات غير المحذوفة | `expenses`, `v_expense_by_category` | `category_name_snapshot` يحفظ اسم التصنيف كما كان وقت العملية |
| سحبيات العمال `withdrawals` | فترة، إجمالي، قائمة، تفصيل حسب العامل | السحبيات غير المحذوفة | `withdrawals`, `v_withdrawal_by_worker` | يظهر التفصيل مستقلاً، لكنه يحسب مرة واحدة ضمن إجمالي المصروفات |
| التقارير `reports` | نوع يومي/شهري/فترة، التاريخ أو من/إلى، ملخص، تفاصيل وتصنيفات | جميع أنواع الحركات ضمن المدى | `v_all_transactions`, `v_daily_totals`, `v_profit_by_item`, `v_expense_by_category`, `v_withdrawal_by_worker` | لا يجري جمع السحبيات مرتين |
| إدارة الأصناف `items` | بحث، اسم، نشط/موقوف، تعديل وإيقاف/تفعيل | أصناف الإدارة | `items` | لا يشترط وجود الصنف هنا لتسجيل الربح |
| إدارة العمال `workers` | بحث، اسم، نشط/موقوف، تعديل وإيقاف/تفعيل | العمال | `workers` | سجل العملية يحتفظ بمعرف العامل ولقطة الاسم |
| تصنيفات المصروفات `cats` | بحث، اسم، نشط/موقوف، تعديل وإيقاف/تفعيل | التصنيفات | `expense_categories` | المسار موجود في كود العرض لكنه ناقص من `PAGES` في المصدر |
| الإعدادات | العملة، النص المخصص، مجلد النسخ الاحتياطي، إدارة القوائم، مسح/إعادة ضبط، سجل التغييرات، معلومات النظام | إعدادات وتاريخ النظام | `app_settings`, ملف إعداد تشغيل خارج DB, `audit_log` | مسار قاعدة البيانات لا يخزن داخل `mowxback.db` |

## 2. حقول النماذج

| موضع الواجهة | الحقل/القيمة | مطلوب؟ حسب الواجهة الحالية | نوع التخزين | الجدول/العمود |
|---|---|---:|---|---|
| إضافة أرباح أصناف | التاريخ | نعم | `YYYY-MM-DD` | `profit_transactions.tx_date` |

| إضافة أرباح أصناف | الكمية | نعم، أكبر من صفر | Integer scaled × 1,000,000 | `profit_lines.quantity_micros` |
| إضافة أرباح أصناف | إجمالي الربح | نعم، أكبر من صفر | Integer scaled × 1,000 | `profit_lines.amount_milli` |
| إضافة أرباح أصناف | ملاحظات الصنف | لا | نص | `profit_lines.notes` |
| إضافة أرباح أصناف | عدد السطور | مشتق | `COUNT(active lines)` | `v_profit_transaction_totals.line_count` |

| إضافة أرباح أصناف | إجمالي الكمية | مشتق | `SUM(quantity_micros)` | `v_profit_transaction_totals.quantity_micros` |

| إضافة مصروف | التصنيف | نعم، نشط عند الإنشاء | FK + لقطة نصية | `expenses.category_id`, `category_name_snapshot` |

| إضافة مصروف | الوصف | نعم في كود الواجهة | نص | `expenses.description` |
| إضافة مصروف | ملاحظات | لا | نص | `expenses.notes` |
| إضافة مصروف | إخفاء/حذف منطقي | غير ظاهر حالياً في UI | timestamp منطقي | `expenses.deleted_at` + `audit_log` |
| سحبية عامل | التاريخ | نعم | `YYYY-MM-DD` | `withdrawals.tx_date` |

| سحبية عامل | المبلغ | نعم، أكبر من صفر | Integer scaled × 1,000 | `withdrawals.amount_milli` |
| سحبية عامل | ملاحظات | لا | نص | `withdrawals.notes` |
| إدارة صنف | الاسم | نعم | نص | `items.name` |
| إدارة عامل | الاسم | نعم | نص | `workers.name` |

## 3. مصدر بيانات كل تقرير

| التقرير | حسابات التجميع | مصادر SQL | شرط التصفية |
|---|---|---|---|
| يومي | مجموع الربح، الكمية، المصروفات، السحبيات، الصافي | `v_daily_totals` | يوم واحد |
| شهري | نفس الإجماليات يومياً/شهرياً | `v_daily_totals` أو استعلام مباشر على `v_all_transactions` | أول يوم الشهر إلى آخر يوم |
| فترة مخصصة | الإجماليات وتفاصيل كل العمليات | `v_daily_totals`, `v_all_transactions` | `tx_date BETWEEN from AND to` |
| أرباح حسب الصنف | مجموع كمية وربح السطور الفعالة | `v_profit_by_item` | الفترة المطلوبة |
| مصروفات حسب التصنيف | مجموع المصروفات حسب `category_id` واسم اللقطة | `v_expense_by_category` | الفترة المطلوبة |
| سحبيات حسب العامل | مجموع السحبيات حسب `worker_id` واسم اللقطة | `v_withdrawal_by_worker` | الفترة المطلوبة |
| تفاصيل العمليات | سجل كل حركة ربح واحدة + كل مصروف + كل سحبية | `v_all_transactions` | الفترة/النوع |

المعادلة المعتمدة:

`net_milli = profit_milli - expense_milli - withdrawal_milli`

`total_expense_milli = expense_milli + withdrawal_milli`

السحبيات ليست صفوفاً إضافية داخل جدول المصروفات، ولا تدخل في إجمالي المصروفات إلا عبر جمع `expense + withdrawal` مرة واحدة.

## 4. علاقات الحقول وإدارة التاريخ

- أسماء الأصناف الحرة محفوظة على `profit_lines.item_name` ولا تحتاج `item_id`.
- `profit_lines.item_id` مرجع اختياري فقط عندما ينطبق صنف إدارة مسجل، وليس شرطاً لإدخال الربح.
- `name_suggestions` لا يرتبط بـ `items` ولا يُحذف عند حذف حركة أو سطر.
- المصروف يحتفظ بـ `category_id` و`category_name_snapshot`. تغيير اسم التصنيف لاحقاً لا يغيّر اسم التصنيف التاريخي للعملية.
- السحبية تحتفظ بـ `worker_id` و`worker_name_snapshot` للسبب نفسه.
- إيقاف سجل صنف/عامل/تصنيف يغيّر `is_active` ولا يمس العمليات المرتبطة به.
- `deleted_at` يخفي السجل من العرض والتقارير، لكنه يحافظ على الصف ومعرفه ومرجعه.
- التواريخ التشغيلية `tx_date` بصيغة `YYYY-MM-DD`، وأوقات التدقيق بصيغة UTC ISO 8601.

## 5. تغييرات الربط التي تحتاجها الواجهة في المرحلة التالية

1. استبدال `Store.load/save` بطلبات `window.mowx` عبر Preload بعد استكمال IPC والRepository.
2. جعل `home`, `ledger`, `profits`, `expenses`, `withdrawals`, `reports`, `items`, `workers`, `cats`, `settings` تستقبل بيانات من SQLite.
3. تحويل `txForm()` القديم للربح إلى حقل اسم حر مع اقتراحات SQLite، وعدم جعل قائمة `items` شرطاً.
4. إضافة تعريف صفحة `cats` في مصفوفة `PAGES` مع المحافظة على التصميم.
5. إلغاء الأزرار الحالية التي تصف البيانات التجريبية أو تنفذ `S.tx=[]` أو `Store.seed()` في نسخة الإنتاج، واستبدالها بتدفق واضح ونسخ أمان.
6. ربط اختيار مسار DB والنسخ الاحتياطي والاستعادة بمربعات حوار Windows الأصلية.
7. استبدال CSV باسم Excel بتصدير `.xlsx` حقيقي، مع إدراج كل سطر ربح على حدة. PDF يبقى عبر الطباعة مع اختبار صفحات التقارير.
8. ضبط تنسيق الأرقام ليعرض 3 منازل لـ JOD/KWD و2 لـ SAR/AED/USD/EGP، ودقة العملة المخصصة 2 افتراضياً.
9. جعل التحديثات المالية وتحديث الاسم الحر وحفظ الاقتراح وسجل التدقيق ضمن SQL Transaction واحدة.
10. حذف أي افتراض عن الاتصال بالإنترنت؛ لا CDN ولا طلب شبكة ولا خادم محلي منفصل.
