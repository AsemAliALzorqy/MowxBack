# MowxBack 0.4.0 — سجل الإصدار

## ملخص الإصدار

إضافة تكامل اختياري مع Telegram لإرسال إشعارات فورية للعامل عند حفظ سحب جديد باسمه، مع المحافظة على وظائف الأرباح والمصروفات والسحبيات الحالية.

## ما أضيف

- إعدادات Telegram اختيارية داخل صفحة الإعدادات؛ التطبيق يعمل دون إعداد البوت.
- يستطيع كل مستخدم إدخال Bot Token لبوت أنشأه بنفسه عبر BotFather.
- التحقق من Token وعرض اسم البوت، مع رفض التشغيل المحلي عند وجود Webhook دون حذفه تلقائياً.
- حفظ Bot Token مشفراً عبر Electron `safeStorage` في مجلد بيانات التطبيق، خارج مجلد المشروع وقاعدة البيانات.
- إضافة رقم هاتف اختياري للعامل، مع الحفاظ على العمال السابقين.
- إنشاء روابط Telegram Deep Link خاصة بالعمال، صالحة 10 دقائق وتستخدم مرة واحدة.
- ربط تلقائي عند فتح الرابط والضغط على Start؛ لا توجد خطوة تأكيد إضافية.
- مشاركة الرابط عبر WhatsApp برسالة جاهزة يرسلها المستخدم بنفسه، أو عرضه في QR حقيقي، أو نسخه.
- حالات العامل: غير مرتبط، بانتظار الربط، انتهت الصلاحية، مرتبط؛ وإدارة وفصل وإعادة ربط الحساب.
- رسالة ترحيب باسم العامل بعد الربط.
- قائمة إرسال دائمة تُنشأ داخل معاملة حفظ السحب نفسها، ثم ترسل الرسالة من Electron Main Process. تستمر محاولة الاتصال بعد انقطاع الشبكة المؤقت حتى عند بدء التطبيق دون إنترنت؛ أما نتيجة إرسال مبهمة بسبب مهلة/انقطاع أثناء الطلب فتتطلب مراجعة يدوية منعاً للتكرار.
- تنسيق إشعار السحب مع شعار MowxBack، واسم منشأة اختياري، والمبلغ والعملة والتاريخ بصيغة يوم/شهر/سنة والوقت ورقم العملية، وملاحظة اختيارية لا تظهر عند فراغ الحقل. تعرض الإعدادات وقت آخر تحقق ناجح من البوت.
- سجل الإشعارات وإعادة المحاولة اليدوية بعد الفشل.
- أحداث تشخيصية لتفعيل البوت والربط والإرسال والأخطاء دون تسجيل Token أو رابط ربط صالح، مع تنقيح أخطاء الشبكة قبل تسجيلها.

## تصميم الإشعار

تستخدم الرسالة تنسيق Telegram HTML المسموح به لإبراز العناوين والمبلغ والفواصل. لا يمكن لرسائل Telegram النصية تطبيق CSS أو التحكم في ألوان الواجهة والخطوط مثل HTML داخل التطبيق؛ لذلك يحافظ القالب على ترتيب الفاتورة المرجعي باستخدام تنسيق Bot API. إذا كانت ملاحظة السحب فارغة، لا يُعرض عنوان الملاحظة أو قسم فارغ.

## قاعدة البيانات

أضيفت migration `003_telegram_notifications.sql`:

- عمود `workers.phone` اختياري.
- جدول `telegram_worker_links` لربط العامل بمعرف المحادثة.
- جدول `telegram_link_tokens` لحفظ بصمة رمز الربط والنسخة المشفرة قصيرة العمر.
- جدول `telegram_notifications` كقائمة إرسال دائمة مرتبطة بعملية السحب.

لم يتغير منطق الحسابات المالية. يستخدم النظام حقل ملاحظات السحب الموجود مسبقاً.

## التشغيل والقيود

- يحتاج Telegram إلى اتصال إنترنت وتشغيل تطبيق MowxBack. إذا كان التطبيق مغلقاً، تبقى الرسائل المعلقة محفوظة وتُراجع عند التشغيل التالي.
- يستخدم التطبيق `getUpdates` (Long Polling)، لذلك يجب ألا يشغّل نفس Bot Token أكثر من نسخة MowxBack في الوقت نفسه. الاستخدام المتزامن على عدة أجهزة يتطلب بنية توزيع/خدمة مركزية غير مشمولة في هذا الإصدار.
- إذا كان Webhook مفعلاً مسبقاً للبوت، يرفض التطبيق تفعيل Long Polling ويطلب من المستخدم معالجة إعداد Webhook يدوياً؛ لا يحذفه تلقائياً.
- يجب على العامل فتح رابط البوت والضغط Start حتى يستطيع البوت مراسلته.
- رابط WhatsApp يستخدم تطبيق/موقع WhatsApp لفتح المحادثة بنص مجهز؛ لا يرسل رسالة WhatsApp تلقائياً، ولا يستخدم WhatsApp Business API.
- يحتاج رقم العامل إلى صيغة دولية مثل `+9627XXXXXXXX` لاستخدام WhatsApp.
- عند فشل طلب إرسال بانقطاع اتصال غير معلوم النتيجة، يصنف الإشعار فاشلاً للمراجعة ولا يعاد تلقائياً لتجنب تكرار رسالة ربما قبلها Telegram. يجب مراجعة محادثة العامل قبل إعادة المحاولة يدوياً.
- عند نقل قاعدة البيانات إلى جهاز Windows آخر، لا ينتقل Bot Token لأنّه مشفر بمخزن أسرار الجهاز. على المستخدم إعادة إدخاله. روابط الربط غير المستهلكة المرتبطة بمخزن أسرار الجهاز السابق قد تحتاج إلى إنشاء رابط جديد.
- أُضيفت آلية تسلسل لبدء/إيقاف خدمة البوت لمنع إنشاء أكثر من Long Polling loop من نقرات متزامنة داخل التطبيق.

## الاختبارات

تم تشغيل `npm test` في بيئة التطوير. شمل الاختبارات المالية وSQLite وRepository وIPC وقوالب PDF والسجلات والفترات واختبارات Telegram (تنسيق الرسائل، اختبارات Bot API بمحاكاة HTTP، والهروب من HTML، وتوليد QR بصيغة SVG).

لم يتم إجراء اتصال حي ببوت Telegram حقيقي لعدم توفر Token اختباري، ولم يتم تشغيل Electron المعبأ أو بناء مثبت Windows في هذه البيئة، كما لم يتم اختبار مسح QR بكاميرا هاتف. يجب إكمال خطوات Windows وBot الاختباري الواردة في `docs/RELEASE-CHECKLIST-AR.md` قبل اعتبار الخاصية معتمدة على جهاز المستخدم.
