## 2. ما يغطيه السلوك الحالي

- حركة ربح تتكون من سطر واحد أو عدة أسطر تحفظ كرأس حركة واحد ضمن Transaction.
- تعديل/حذف سطر منفرد، وإعادة جمع المبالغ والكميات من الأسطر غير المحذوفة.
- اختفاء الحركة من دفتر العمليات عند حذف كل أسطرها منطقياً مع بقاء الصفوف وسجل التدقيق.
- المصروفات وسحبيات العمال CRUD مع Soft Delete.
- التقارير تستعلم من SQLite، وتضيف السحبيات إلى إجمالي المصروفات مرة واحدة فقط.
- تغيير العملة يحفظ إعداداتها ولا يحدث قيم `amount_milli` المخزنة.
- اقتراحات الأسماء مستقلة عن `items` وتبقى بعد حذف الحركة المرتبطة بها.
- مستورد JSON يمنع تكرار الملف بالبصمة، ويشترط قاعدة أعمال فارغة، وينفذ الاستيراد داخل Transaction.
- نسخة JSON القابلة للتصدير تشمل العمليات المحذوفة منطقياً وتفاصيل خطوط الأرباح التاريخية وسجل التدقيق.
- قاعدة البيانات على القرص استمرت بعد إغلاق Node `DatabaseSync` وإعادة فتحها.

## 3. اختبارات لم تنفذ

| الاختبار | الحالة والسبب |
|---|---|
| تشغيل Electron Main/Renderer فعلياً | غير منفذ؛ dependencies غير مثبتة بنجاح ولم يتم تشغيل الواجهة داخل Electron. |
| `better-sqlite3` في Electron ABI | غير منفذ؛ يحتاج تثبيت الحزمة وإعادة بناء الـnative module. |
| تشغيل تطبيق Windows وإغلاقه وإعادة فتحه | غير منفذ على Windows؛ اختبار القرص أعلاه يستخدم Node `node:sqlite` فقط. |
| إنشاء Installer NSIS x64 | غير منفذ؛ لم يشغّل GitHub Actions أو `electron-builder` في Windows. |
| نوافذ اختيار المجلد الأصلية ونقل القاعدة | غير منفذ end-to-end في Windows. منطق lifecycle موجود ويجب التحقق منه على النظام المستهدف. |
| Backup/restore باستخدام `better-sqlite3` Backup API | الكود موجود، لكن دورة Electron الأصلية لم تُشغّل هنا. |
| اختبار كل نافذة من الواجهة وتفاعلها بصرياً | غير منفذ end-to-end؛ تم فحص صياغة الملفات وعقد IPC فقط. |
| استيراد JSON فعلي للمستخدم | غير منفذ؛ لم يرفق المستخدم ملفه. اختبر المستورد بfixture داخلي. |
| عدم الاتصال بالإنترنت على Windows | لم ينفذ اختبار حقيقي؛ الموارد الحالية محلية ولا يوجد CDN في index. |
| XLSX حقيقي / PDF | XLSX غير منفذ؛ المتاح CSV. PDF يفتح مسار الطباعة ولم يُختبر في Windows. |
| النسخ التلقائي اليومي | غير مفعل. |

## 4. مصفوفة الاختبار المطلوبة قبل اعتماد الإنتاج

1. تثبيت الحزم في Windows ثم `npm run rebuild:native`, `npm test`, `npm start`.
2. إنشاء قاعدة فارغة والتأكد من ظهور تصنيفات الطعام والمحروقات والصيانة فقط دون Demo.
3. حفظ حركة ربح بسطر واحد مباشرة، ثم حركة بعدة أسطر، وإغلاق البرنامج وإعادة فتحه.
4. تعديل سطر ربح وحذفه، ثم حذف جميع الأسطر والتحقق من اختفائها من الدفتر مع بقاء التدقيق.
5. إضافة/تعديل/حذف مصروف وسحبية، ثم التحقق من التقرير أن السحبيات لم تحتسب مرتين.
6. إضافة/تعديل/إيقاف/تفعيل عامل وصنف وتصنيف، والتحقق من السجلات التاريخية.
7. تغيير العملات بين JOD وKWD وUSD وcustom، وفحص عدم تغير أعداد `amount_milli`.
8. استيراد عينة JSON من كل صيغة مدعومة v1/v2/v3، ومقارنة IDs والأعداد والمجاميع، ثم محاولة الاستيراد ثانية للتأكد من المنع.
9. إنشاء Backup، فحصه، واستعادته بعد الاحتفاظ بنسخة أمان.
10. نقل قاعدة البيانات إلى مجلد جديد، ومقارنة السجلات والإجماليات، ثم محاكاة فقدان القرص للتأكد من منع إنشاء قاعدة جديدة بصمت.
11. بناء NSIS x64 وتشغيل المثبت على Windows، وفصل الإنترنت ثم تجربة كل صفحة وتقارير ونسخ احتياطي.
12. اختبار ترقية نسخة قديمة من مخطط قاعدة البيانات عند إضافة Migration لاحقة.
