# تقرير التسليم — MowxBack Database Foundation

**التاريخ:** 23 نوفمبر 2026  
**المصدر:** `MowxBack-v3 (١).zip`  
**النتيجة:** أساس SQLite + تقارير تحليل + بداية Electron، دون إعادة تصميم الواجهة ودون ربط صفحات التطبيق بعد.

## 1. ما تم إنجازه فعلياً

### تحليل المصدر

- فحصت الملفات التسعة الفعلية: `index.html`, `css/main.css`, `js/app.js`, `js/storage.js`, `js/utils.js`, `js/backup.js`, `README.md`, `docs/report-v2.md`, `docs/report-v3.md`.
- حللت الصفحات والحقول والنماذج والأزرار وحسابات المبالغ والاقتراحات وتصدير التقارير والإعدادات ومسارات LocalStorage.
- أنشأت `docs/project-audit.md` و`docs/ui-data-map.md`.
- وثقت تعارض/فجوة صفحة التصنيفات، مسار تعديل الربح القديم، سجل تغييرات القوائم، مسح البيانات وإعادة الضبط، CSV، النسخ الاحتياطي، وتوليد البيانات التجريبية عند غياب LocalStorage.

### تصميم SQLite

- أنشأت `database/schema.sql` و`database/migrations/001_initial.sql`.
- الجداول: `profit_transactions`, `profit_lines`, `expenses`, `withdrawals`, `items`, `workers`, `expense_categories`, `name_suggestions`, `audit_log`, `app_settings`, `schema_migrations`, `legacy_imports`.
- أنشأت Views: `v_profit_transaction_totals`, `v_all_transactions`, `v_daily_totals`, `v_profit_by_item`, `v_expense_by_category`, `v_withdrawal_by_worker`.
- أضفت Foreign Keys وCHECK Constraints والفهارس وSoft Delete ومفاتيح حفظ IDs.
- فصلت أسماء الاقتراحات عن سجل الأصناف الإدارية.
- جعلت المبالغ Integer بوحدة الألف من وحدة العملة، والكميات Integer بوحدة المليون، لتجنب الحسابات العائمة.
- أضفت `docs/database-design.md` و`docs/database-erd.md`.

### طبقة Repository والترحيل

- أضفت `src/database/repository.js` لإنشاء/تحديث/حذف حركة الربح وأسطرها، وإضافة/تعديل/حذف المصروفات والسحبيات منطقياً، وتسجيل القوائم والاقتراحات وسجل التغييرات ضمن معاملات.
- أضفت `src/database/legacy-import.js` للتحقق من JSON wrapper `schema:2` ثم قراءة `data.v` الداخلي بصورة مستقلة، وتحويل ربح الصنف المفرد إلى خط واحد، والمحافظة على معرفات الحركات والسجلات والسطور الموجودة، ومنع استيراد الملف ذاته مرتين.
- مستورد JSON يشترط قاعدة أعمال فارغة ويرجع كامل المعاملة عند أي خطأ. لم يُنفذ استيراد فعلي لعدم وجود ملف JSON خاص بالمستخدم.
- أضفت `src/database/lifecycle.js` للنسخ الاحتياطي والنقل والاستعادة والتحقق من محتوى القاعدة.

### أساس Electron

- أضفت `electron/main.js` و`electron/preload.js` مع IPC محدود.
- إعدادات الأمان: `contextIsolation:true`, `nodeIntegration:false`, `sandbox:true`, `webSecurity:true` وCSP محلية.
- اختيار مجلد البيانات من نافذة Windows أصلية، وإنشاء `Data/mowxback.db`، وحفظ المسار خارج قاعدة البيانات.
- لا ينشئ البرنامج DB فارغة صامتة إذا فُقد الملف المسجل؛ يطلب تحديد القاعدة أو استعادة نسخة.
- أضفت عمليات Electron أساسية للحالة والفحص ونقل القاعدة واختيار/إزالة مجلد النسخ، إنشاء نسخة تلقائية إلى المجلد أو حفظ باسم عبر نافذة Windows، الاستعادة واستيراد JSON.
- أضفت `package.json` وGitHub Actions لبناء Windows x64، مع الإصدارات التي تم التحقق من أحدثها وقت الإعداد.

## 2. ما اختبرته فعلياً

نفذت **15/15 اختبار SQLite ناجحاً** على SQLite 3.46.1:

- إنشاء الجداول والقيود والعلاقات والـViews.
- `PRAGMA integrity_check` أعاد `ok`.
- `PRAGMA foreign_key_check` لم يرجع مخالفات.
- ربح مفرد ومتعدد الأصناف في حركة واحدة.
- إعادة الحساب بعد تعديل سطر وحذف سطر.
- إخفاء حركة بعد حذف جميع السطور منطقياً مع بقاء سجلها.
- إدخال مصروف وسحبية والتحقق من أن السحبية لم تتكرر.
- إيقاف عامل مع بقاء البيانات التاريخية.
- رفض المبالغ الصفرية وFK غير الموجود والتواريخ غير الصالحة.
- تقارير بالفترة وتجميع حسب الصنف.
- استقلال اقتراحات الأسماء.
- تخزين JSON قبل/بعد في التدقيق.

كما نُفذت اختبارات 12 assertion لتحويل المبالغ والكميات إلى integer scaled، ونجحت. تم فحص صياغة JavaScript بNode.js. التفاصيل في `docs/test-plan.md`.

## 3. ما لم يُنفذ أو لم يختبر بعد

- لم أربط صفحات `app.js` بقاعدة SQLite؛ الواجهة الحالية لا تزال تعتمد LocalStorage. هذه خطوة تالية وليست مخفية في التسليم.
- لم أشغل Electron أو `better-sqlite3` فعلياً لأن الحزم الأصلية لم تُثبت في البيئة.
- لم أنشئ ملف `package-lock.json` ولم أنفذ بناء Windows NSIS؛ يحتاج ذلك Windows runner أو GitHub Actions.
- لم أختبر نوافذ اختيار المجلدات أو النقل والاستعادة على جهاز Windows حقيقي.
- لم أستورد JSON مستخدماً؛ ZIP لا يحوي LocalStorage أو ملف النسخ الصادر من المتصفح.
- لم أضف تصدير XLSX حقيقياً في هذه المرحلة؛ الواجهة الحالية لا تزال CSV، وPDF ما زال طباعة.
- النسخ الاحتياطي التلقائي اليومي لم يُفعل؛ تمت كتابة سياسة موصى بها في `docs/windows-electron.md`.
- لم أغير شكل الواجهة؛ أضيفت فقط سياسة CSP إلى `index.html` لأمان Electron.

## 4. ملاحظات لا يجوز تجاهلها قبل إدخال بيانات العمل

1. عند تشغيل الواجهة الحالية كواجهة متصفح أو Electron قبل مرحلة الربط، سيظل `Store.seed()` قادراً على إنشاء بيانات تجريبية في LocalStorage. لا تستخدم الواجهة الحالية لتسجيل معاملات المصنع على أنها بيانات SQLite.
2. قاعدة SQLite التي ينشئها Main Process لا تُستخدم حالياً من `app.js`؛ قاعدة الأساس لا تعني اكتمال البرنامج النهائي.
3. لا تضغط «مسح البيانات التجريبية» في الواجهة الحالية مع بيانات مهمة؛ الكود الحالي يمسح كل `S.tx` وكل `S.log`. ولا تستخدم «إعادة ضبط» لأنها تعيد بيانات Demo.
4. يجب الحصول على JSON backup من المتصفح قبل ترحيل بيانات حقيقية، ومقارنة عدد الحركات ومجموع الأرباح والمصروفات والسحبيات والسطور قبل/بعد الاستيراد.

## 5. الخطوة التالية المقترحة

العمل التالي يجب أن يكون **ربط التخزين فقط دون إعادة تصميم**: تجهيز IPC CRUD/report endpoints مستندة إلى `repository.js`، ثم استبدال وصول `app.js` إلى `Store` بمحول تخزين مع الحفاظ على دوال العرض والـCSS، ثم اختبار مسار تعديل الربح المفرد وصفحة التصنيفات ومسح Demo، وبعد ذلك إضافة XLSX وواجهات Windows لإدارة مسار DB والنسخ والاستعادة. لا تُشغّل بيانات إنتاج قبل اكتمال هذا الربط واختبار JSON migration على نسخة حقيقية.

## 6. حفظ المصدر الأصلي

- لم يتم تعديل ملف ZIP المرفق الأصلي.
- أُضيفت نسخة مطابقة من ملفات المصدر التسعة داخل `reference/original-source/` للمقارنة والرجوع، بينما ملفات المشروع في الجذر هي نسخة العمل التي تتضمن إضافات الأساس وCSP والتوثيق.
